# Jupyter Environment & Data Management

This document explains how the Jupyter notebook environment works in the AEDES project, how data flows through the system, and how notebooks are executed within the surveillance dashboard infrastructure.

## Overview

The AEDES project uses Jupyter notebooks for interactive analysis and automated reporting. Notebooks run in two contexts:

1. **Development Environment** — Manual execution in VS Code or Jupyter Lab for exploration and testing
2. **Automated Pipeline** — GitHub Actions workflow executes notebooks daily, converting output to HTML for the dashboard

## Data Fetching & Refresh Cycle

### Fetch Script: `scripts/fetch_surveillance_data.py`

**When It Runs:**
- Daily at 6 AM UTC (via GitHub Actions `surveillance-dashboard.yml`)
- On-demand by pushing to `notebooks/` or `scripts/` directories
- Manual trigger via GitHub Actions UI

**What It Does:**
1. Calls public APIs (CDC, NASA POWER, iNaturalist, NOAA)
2. Caches responses as JSON in `/data/surveillance/`
3. Handles API failures gracefully (saves sentinel files so notebooks use fallback data)
4. Timestamps all fetches (`"fetched": "2026-05-18"`)

**Key Functions:**

```python
# fetch_cdc_wonder_wnv() → /data/surveillance/wnv_colorado.json
# fetch_cdc_wonder_lyme() → /data/surveillance/lyme_colorado.json
# fetch_nasa_power_colorado() → /data/surveillance/climate_colorado_90d.json
# fetch_inaturalist_ticks() → /data/surveillance/inaturalist_ticks_colorado.json
# fetch_inaturalist_mosquitoes() → /data/surveillance/inaturalist_mosquitoes_colorado.json
```

**Data Freshness:**
- WNV/Lyme: Annual totals (updated once per year by CDC)
- Climate: 90-day rolling window (refreshed daily)
- iNaturalist: Latest observations (updated with each fetch)

### Fallback Behavior

If an API is unavailable, the fetch script saves a sentinel file:

```json
{
  "fetched": "2026-05-18",
  "source": "unavailable",
  "data": []
}
```

Notebooks detect this and either:
- Use cached data from previous runs, or
- Generate synthetic/sample data for demonstration

## Notebook Execution Pipeline

### Local Development

**Starting Jupyter:**

```bash
cd /workspaces/aedesproject-uif
jupyter lab notebooks/
```

**Notebook Setup (typically first cell):**

```python
import sys
import os
sys.path.insert(0, '/workspaces/aedesproject-uif/src')

# Define paths
PROJECT_ROOT = '/workspaces/aedesproject-uif'
DATA_DIR = os.path.join(PROJECT_ROOT, 'data', 'surveillance')
OUTPUT_DIR = os.path.join(PROJECT_ROOT, '_site', 'climate_data')

# Import project modules
from aedesproject_uif.data_extraction.climate import thermal_accumulation
from aedesproject_uif.data_extraction.climate import climate_data_fetcher
```

### Automated Execution (GitHub Actions)

**Workflow:** `.github/workflows/surveillance-dashboard.yml`

**Steps:**
1. Checkout repository
2. Set up Python 3.11 environment
3. Run `scripts/fetch_surveillance_data.py` (data refresh)
4. Execute all notebooks with `jupyter nbconvert --execute`
5. Convert outputs to HTML
6. Generate landing page with `scripts/generate_dashboard.py`
7. Deploy to GitHub Pages

**Command Used:**

```bash
jupyter nbconvert \
  --to html \
  --execute \
  --ExecutePreprocessor.timeout=300 \
  --output-dir _site/notebooks \
  notebooks/*.ipynb
```

### Loading Data from Surveillance Files

**Pattern 1: Direct JSON Load**

```python
import pandas as pd

# Load with fallback to sample data if missing
try:
    wnv_data = pd.read_json(os.path.join(DATA_DIR, 'wnv_colorado.json'))
except FileNotFoundError:
    print("⚠ WNV data not found; using sample data")
    wnv_data = pd.DataFrame({
        'year': [2024],
        'neuroinvasive': [12],
        'deaths': [0]
    })
```

**Pattern 2: Check Source Availability**

```python
data_file = os.path.join(DATA_DIR, 'wnv_colorado.json')
if os.path.exists(data_file):
    with open(data_file) as f:
        import json
        content = json.load(f)
        if content.get('source') == 'unavailable':
            print("⚠ Data unavailable; using fallback")
        else:
            wnv_data = pd.DataFrame(content.get('data', []))
```

## Best Practices for Notebooks

### 1. Path Handling

✅ **DO:**
```python
import os
DATA_DIR = os.path.join(PROJECT_ROOT, 'data', 'surveillance')
data = pd.read_json(os.path.join(DATA_DIR, 'wnv_colorado.json'))
```

❌ **DON'T:**
```python
data = pd.read_json('../data/surveillance/wnv_colorado.json')  # Breaks in GitHub Actions
data = pd.read_json('/workspaces/.../data/...')  # Not portable
```

### 2. Cell Isolation

✅ **DO:** Define paths and imports in first cells, reuse throughout

❌ **DON'T:** Import modules or set paths in the middle of analysis cells

### 3. Fallback Data

✅ **DO:** Always handle missing data gracefully
```python
try:
    data = pd.read_json(path)
except FileNotFoundError:
    data = pd.DataFrame()  # or create sample data
```

### 4. Output Persistence

✅ **DO:** Save results to `/_site/` for dashboard
```python
output_path = os.path.join(OUTPUT_DIR, 'results.csv')
os.makedirs(OUTPUT_DIR, exist_ok=True)
df.to_csv(output_path, index=False)
```

### 5. Reproducibility

✅ **DO:** Set random seeds and document data sources
```python
import numpy as np
np.random.seed(42)

# Document: Data from CDC NNDSS annual summary (fetched 2026-05-18)
```

## Troubleshooting

### Notebook Won't Find Data

**Symptom:** `FileNotFoundError: /data/surveillance/wnv_colorado.json`

**Solution:**
1. Check that data fetch ran: `ls /data/surveillance/`
2. Verify path construction: `print(DATA_DIR)` in notebook first cell
3. If empty, run manually: `python scripts/fetch_surveillance_data.py`

### Imports Fail (Module Not Found)

**Symptom:** `ModuleNotFoundError: No module named 'aedesproject_uif'`

**Solution:**
1. Add to first notebook cell:
```python
import sys
sys.path.insert(0, '/workspaces/aedesproject-uif/src')
```
2. Or install package: `pip install -e . --no-deps` in terminal

### GitHub Actions Workflow Fails

**Symptom:** "nbconvert failed" or "Module not found"

**Check:**
1. YAML syntax: `.github/workflows/surveillance-dashboard.yml` is valid
2. Dependencies: all required packages listed in workflow `pip install` steps
3. Notebook errors: test locally first with `jupyter nbconvert --execute`

### API Unavailable (Offline)

**Symptom:** Climate/CDC data shows `"source": "unavailable"`

**Expected:** Workflow continues with fallback data (notebooks auto-detect)

**Result:** Dashboard builds but uses sample/cached data until API recovers

## Data Retention & Updates

### What Persists

- `/.github/workflows/` — Automation configuration (permanent)
- `/notebooks/` — Analysis templates (permanent)
- `/scripts/` — Data fetching & generation (permanent)
- `/_site/` — Generated output (regenerated daily)

### What Gets Refreshed

- `/data/surveillance/` — Fetched fresh each run
- Notebook `.html` outputs — Regenerated from latest `.ipynb`
- Dashboard index page — Built from current data

### Historical Data

To preserve historical trends, notebooks should save processed results to `/processed/` or `/_site/` directories:

```python
# Save historical archive
output_path = os.path.join(PROJECT_ROOT, 'processed', 'climate_disease_archive.csv')
historical_data.to_csv(output_path, index=False)
```

## Performance Considerations

### Notebook Execution Time

- Typical notebook: 30-60 seconds
- With API calls: 2-5 minutes (network-dependent)
- GitHub Actions timeout: 30 minutes (configurable)

**Timeout in workflows:**

```yaml
jobs:
  build-and-deploy:
    timeout-minutes: 30  # Adjust if notebooks need more time
```

### Memory Usage

- Small datasets (< 100 MB): No issues
- Large climate/satellite data: May need `--memory-limit` if hitting limits

**For large notebooks, increase runner memory via:**

```yaml
runs-on: ubuntu-latest  # 7 GB default
# Consider: ubuntu-latest-8-cores (larger instance)
```
